# Переезд прода на новую версию. Чек-лист

Сервер и база остаются те же. Меняется только код боевого сервиса.
Заметки, звёзды, выгрузки, комментарии, пользователи, токены Allegro остаются в боевой базе.
Новая версия только добавляет таблицы и колонки.

Проверено репетицией: старая версия → база с данными → новая версия → снова старая версия.
Ни одна строка в старых колонках не изменилась. Откат рабочий.

---

## За день до переезда

- [ ] **Свежая копия прода в v2.** GitHub → Actions → «Клон прода в v2». День смотрим новую версию на реальных данных: заказы, заметки, звёзды и выгрузки на месте.
- [ ] **Каталог и база знаний в v2.** Если в v2 правили что-то руками, а не через сид, это живёт только в базе v2. Выгрузить и перенести.

## Переезд (вечер буднего дня, не пятница)

1. [ ] **Бэкап прода.** Панель → Users → «Pobierz teraz» сохранить себе. Плюс снимок базы в Railway: Postgres → Backups.
2. [ ] **Код v2 в репо `polish_type` обычным коммитом поверх**, без force-push. Старый коммит остаётся в истории для отката.
3. [ ] **Переменные боевого сервиса.** Ничего не удалять, только добавить:
   - `ERLI_KEY`, `ERLI_SELLER_NAME`, `ERLI_MARKET` — как в v2, если Erli нужен на проде;
   - `BACKUP_GITHUB_TOKEN`, `BACKUP_GITHUB_REPO` — ночной бэкап;
   - `MCP_TOKEN` — свой, не такой как у v2;
   - **НЕ** задавать `INSTANCE_ID`, `SYNC_ENABLED`, `BCRYPT_MIGRATE`. Без них сервис сам считает себя продом, а пароли остаются в старом формате, чтобы откат был возможен.
4. [ ] **Деплой.** В логах должно быть:
   - `auto-migrations applied`
   - `права «Каталог» и «База знаний» выданы: N польз.`
   - `scheduler started`
5. [ ] **Проверка:**
   - `/api/instance` → `is_prod_instance: true`, `sync_enabled: true`;
   - зайти своим логином;
   - «Stara wersja» в шапке → старый вид, «✨ Nowa wersja» → новый;
   - поставить звезду в одном виде и увидеть её в другом;
   - через 15 минут в логе синка есть новые заказы со всех магазинов;
   - тестовый заказ на сайте пришёл вебхуком.

## Откат (если что-то не так)

Railway → боевой сервис → Deployments → предыдущий деплой → **Redeploy**.
Старый код работает на той же базе: новые таблицы и колонки он просто не видит.
